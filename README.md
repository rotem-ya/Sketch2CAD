# Sketch2CAD

כלי מקומי (Windows) שהופך סקיצות, צילומים, פרטים טיפוסיים וקבצי PDF לשרטוטי AutoCAD (DXF, DWG, PDF). הכלי כולל ניהול פרויקטים, קוד פנימי למסמכים, תבניות כותרת, קטלוג פריטים עם מקורות, בדיקות הנדסיות, כתב כמויות, תיק הגשה וחיפוש, בעברית ובאנגלית.

- **אפיון:** [docs/SPEC.md](docs/SPEC.md)
- **פורמטים פנימיים ו-API:** [docs/FORMATS.md](docs/FORMATS.md)
- **דוגמאות:** `examples/`. מפרטי `spec.json` של חיבור הגמל ושל הצעת תעלות מבנה P.
- **אב-טיפוס:** `prototypes/`. הסקריפטים המקוריים, והקבצים שהם הפיקו ב-`prototypes/outputs/`.

## התקנה והפעלה (Windows)
1. מורידים את התוכנה: **[Sketch2CAD-main.zip](https://github.com/rotem-ya/Sketch2CAD/archive/refs/heads/main.zip)**, ומחלצים לתיקייה קבועה, למשל `C:\Sketch2CAD`. לא לתיקייה תחת `Program Files` (Windows חוסם שם כתיבה, והתוכנה צריכה לשמור הגדרות ועדכונים ליד עצמה).
2. לוחצים פעמיים על `install.bat`. הקובץ מאתר Python נתמך (3.11 עד 3.14; ל-3.15 ומעלה עדיין אין חבילות מוכנות) ומתקין Python 3.12 אם אין (דרך winget), מתקין את כל הספריות ויוצר קיצור דרך "Sketch2CAD" בשולחן העבודה. לוקח כמה דקות, ורק בפעם הראשונה. בסוף הוא שואל איפה לשמור את **הנתונים** (הגדרות, אינדקס חיפוש, קטלוג ותבניות אישיות): Enter לברירת המחדל (`%APPDATA%\Sketch2CAD`), או נתיב בכונן אחר, למשל `E:\Sketch2CAD\Data`. אפשר לשנות אחר כך במסך ההגדרות.
3. זהו. מכאן התוכנה עובדת כמו "רכש ומלאי": השרת שלה רץ ברקע כל הזמן, עולה לבד עם Windows (קיצור בתיקיית Startup) ומופעל מחדש לבד אם נפל. פותחים אותה בדפדפן בכתובת http://localhost:8517 (שומרים כמועדף) או מקיצור הדרך "Sketch2CAD" בשולחן העבודה, שמוודא שהשרת רץ ופותח את הדפדפן. בלי חלון שחור. `stop.bat` עוצר את שרת הרקע (עד הכניסה הבאה ל-Windows או `run.bat`), `uninstall.bat` מבטל את ההפעלה האוטומטית בלי למחוק דבר, ו-`run-debug.bat` מריץ בחלון שמציג את כל ההודעות, לבירור תקלות (אחרי `stop.bat`). ההודעות נשמרות תמיד ב-`logs\app.log` בתיקיית הנתונים. למה לא שירות Windows כמו ברכש: שירות רץ מחוץ לסשן של המשתמש ולא רואה את כונן Google Drive, לא יכול לפתוח חלון בחירת תיקייה ולא לפתוח קובץ ב-AutoCAD; לכן השרת רץ בסשן המשתמש, מוסתר, תחת משגיח קטן. אם קיצור ה-Startup נמחק, ההפעלה הבאה יוצרת אותו מחדש ומצביעה על תיקיית ההתקנה הנוכחית. אותו תיקון, וניקוי של קובץ pid שנשאר מתהליך שכבר לא רץ: `pythonw.exe -m sketch2cad.launcher --repair` מתוך התיקייה (או `.venv\Scripts\pythonw.exe`).
4. **DWG:** אם מותקנים AutoCAD או AutoCAD LT עם accoreconsole, התוכנה משתמשת בהם אוטומטית להמרה ל-DWG. בלי accoreconsole מגדירים בהגדרות את הנתיב ל-[ODA File Converter](https://www.opendesign.com/guestfiles/oda_file_converter), שהוא חינמי לשימוש פנימי. בלשונית "תוצרים" יש כפתור "פתח באוטוקד".
5. אין קריאת מודל בתוך התוכנה ואין מפתח. שיקול הדעת נעשה דרך גשר העבודה. אפשר להפעיל על אותו מחשב ריצה מקומית של Claude (המנוי שכבר מחובר במחשב, בלי מפתח) שכותבת את התשובה לתיבת הקבלה. בלי הגדרה, «שלח לסוכן» ו«קבל מהסוכן» נשארים ידניים.

**איפה הקבצים:** התוכנה עצמה בתיקיית ההתקנה (למשל `C:\Sketch2CAD`). הפרויקטים בתיקייה שבוחרים לכל פרויקט (ברירת המחדל נקבעת במסך ההגדרות, למשל `E:\Sketch2CAD\Projects`). הנתונים המשותפים (הגדרות, אינדקס חיפוש, קטלוג ותבניות אישיות) בתיקיית הנתונים, שנבחרת ב-`install.bat` או במסך ההגדרות ונשמרת בקובץ `data_home.txt` ליד התוכנה. שינוי תיקיית הנתונים מעתיק אליה את הנתונים הקיימים, ותיקייה שכבר יש בה נתונים (למשל ממחשב קודם) נשארת כמו שהיא. עדכון גרסה לא נוגע בשום דבר מזה.

**עדכון גרסה:** בתחתית התפריט הצדדי מוצגת הגרסה המותקנת. התוכנה בודקת לבד אם יש גרסה חדשה (או בכפתור "🔄 בדוק עדכונים"). כשיש, לוחצים "⬇️ עדכן עכשיו": התוכנה נסגרת בלי חלון שחור, מורידה את הגרסה החדשה, מתקינה ספריות רק אם `requirements.txt` השתנה, ונפתחת מחדש. הודעות העדכון נשמרות ב-`logs\update.log` בתיקיית הנתונים. אם התוכנה לא נפתחת בכלל, סוגרים אותה ומפעילים `update.bat`. העדכון לא נוגע בפרויקטים ובהגדרות.

## מה יש בתוכנה
| מסך | מה עושים בו |
|---|---|
| פרויקטים | יצירת פרויקט (הפרטים ממולאים ידנית, ובחירת תיקייה בכפתור 📂), ותיקייה קבועה לכל פרויקט שאפשר להעביר. מבנה התיקייה: `00_Sources`, `10_Drawings`, `20_Imports`, `90_Archive` |
| פרויקט | רשימת מסמכים עם סינון וחיפוש, מסמך חדש עם קוד אוטומטי, **סט הדפסה** (PDF אחד עם רשימת גיליונות וסימניות), הגדרות |
| מסמך | פרטים, מקורות (הטקסט מכל קובץ נכנס לחיפוש, גם ממיילים), **שרטוט** (מפרט מפרט טיפוסי, מסקיצה דרך הגשר, או מ-JSON, ובחירת תבנית כותרת ושינוי הכותרת; **סימון ותיקון לפי בקשה**: סימון על השרטוט בעט חופשי ובקווים ישרים, «שלח לסוכן» ואז «קבל מהסוכן», והשרטוט מוחל ומופק מחדש עם אפשרות לבטל), **בדיקות**, **כתב כמויות** (Excel), תוצרים, **תיק הגשה**, **השוואת מהדורות**, מהדורות |
| ייבוא והמרה | פתיחה ותצוגה של DWG, DXF, PDF, תמונות ו-IFC. המרות: PDF ל-DXF או DWG בקנה מידה, DXF ל-DWG ובחזרה, IFC לתוכנית DXF. שמירה כמסמך בפרויקט |
| מייל | מעלים מייל של בודק (msg. מ-Outlook או eml.). התוכנה קוראת את ההערות ואת הקבצים המצורפים, מזהה לבד לאיזה פרויקט ומסמך הם שייכים (קוד המסמך, קבצים של המסמך, קוד הפרויקט ומילים משותפות; אפשר לשנות), ושומרת את המייל והקבצים במקורות המסמך. תיקון השרטוט נעשה אחר כך במסך השרטוט, עם «שלח לסוכן» / «קבל מהסוכן» |
| תבניות כותרת | צפייה בתבניות ועריכתן, ושמירת עותק כתבנית אישית |
| קטלוג | אביזרים עם מידות ומקור לכל מידה (הגשה וקובץ). מידות בלי מקור מסומנות. שמירה לקטלוג הפרויקט או לקטלוג האישי |
| חיפוש | חיפוש בכל הפרויקטים לפי קוד, כותרת, תיאור, תגיות ותוכן הקבצים. חיפוש "גמל" מוצא גם "לגמל" |

**Revit:** אין קורא RVT חינמי ומקומי. ב-Revit מבצעים File > Export > IFC ומייבאים את ה-IFC.

## גשר עבודה (הדרך היחידה לשיקול דעת)
התוכנה עצמה לא קוראת למודל ולא לרשת בשביל שרטוט. היא מייצאת חבילת עבודה לסוכן חיצוני ומייבאת ממנו spec. שורת הפקודה:

```bash
python -m sketch2cad.bridge export <תיקיית פרויקט או שרטוט> (--out <תיקייה> | --to-outbox) [--request "..."]
python -m sketch2cad.bridge import (<תשובה.json> | --from-inbox) --drawing <תיקיית שרטוט> [--apply]
```

הייצוא כותב מקורות (סקיצה, תמונות, PDF), את `spec.json` הנוכחי אם יש, שורות קטלוג, את פורמט ה-spec, תצוגה מסומנת אם יש, בקשת תיקון אופציונלית, ו-`manifest.json`. `--to-outbox` שם את החבילה ב-`<פרויקט>/agent_exchange/outbox/`, והתשובה חוזרת אל `agent_exchange/inbox/`. במסך השרטוט, «שלח לסוכן» ו«קבל מהסוכן» עושים את זה: בלשונית הסקיצה גם כשאין עדיין מפרט, וב«סימון ותיקון לפי בקשה» אחרי שיש שרטוט. הייבוא מאמת, מריץ את הבדיקות ההנדסיות, ומרנדר לתיקיית ניסיון (כולל DWG אם יש ממיר). בלי `--apply`, ובממשק בלי «החל על השרטוט», קובץ ה-spec לא משתנה. פירוט: [docs/BRIDGE.md](docs/BRIDGE.md).

## ריצה מקומית (רשות)
כבויה עד שמגדירים אותה במסך ההגדרות:

1. נתיב `claude.exe`. ריק = חיפוש ב-PATH וב-`%USERPROFILE%\.local\bin`.
2. תיקיות חשבון, שורה לכל אחת, לפי הסדר. כל תיקייה היא `CLAUDE_CONFIG_DIR` של כניסה שכבר קיימת במחשב. אין מפתח.
3. לסמן «להריץ את Claude כשנשלחת חבילה».
4. זמן מרבי לריצה, בשניות (ברירת מחדל 600). לכל ריצה יש זמן משלה.

כשחבילה נכתבת ל-`agent_exchange/outbox`, המשגר שכבר רץ (או מסך השרטוט) פותח `agent_exchange/claude_tasks/<זמן>-<חבילה>/` עם `TASK.md`, `p.txt` ו-`run.ps1`, ומפעיל את `claude.exe` בלי חלון. Claude כותב `reply.json` רק בתיקיית המשימה, ואחר כך `REPORT.md` ו-`DONE.txt`. התוכנה בודקת שהמעטפת תקינה ומעבירה אותה אל `agent_exchange/inbox/<חבילה>-reply.json`. תשובה חלקית לא מגיעה לתיבה. אם `run.log` מראה מגבלת שימוש, או שהריצה נגמרת בלי תשובה תקינה, מנסים את כל תיקיות החשבון לפי הסדר.

במסך השרטוט מופיע: בתור / Claude עובד / התשובה מוכנה / נכשל. בכישלון מוצג סוף `run.log`. «קבל מהסוכן» והבדיקות נשארים חובה, ומחילים רק אחרי שרואים את הניסיון. בלי ההגדרה, הגשר הידני עובד כמו קודם.

`install.bat` מתקין רק את `requirements.txt`. אין שם חבילת מודל, ובניית `.venv` מחדש לא מתקינה אחת. שדה מפתח ישן בקובץ ההגדרות נמחק בטעינה ובשמירה.

**אזהרה:** חבילה עם שרטוטי לקוחות נשארת אצל המשתמש. לא מכניסים אותה לריפו הציבורי.

## בדיקות
```bash
pip install -r requirements.txt
python -m pytest -q
```
את בדיקת ההמרה ל-DWG מריצים כשמשתנה הסביבה `ODA_CONVERTER` מצביע על הממיר. בלי הממיר הבדיקה מדולגת.
