# גשר עבודה

התוכנה עושה את העבודה המכנית: אריזת חומר, אימות, בדיקות ורינדור. שיקול הדעת נעשה רק מחוץ לתוכנה, דרך המודול `sketch2cad/bridge.py`. אין בתוכנה קריאת מודל, מפתח API, או חבילת `sketch2cad/ai`.

```text
תיקיית שרטוט  --export-->  חבילת עבודה  -->  סוכן חיצוני
                                                      |
תיקיית שרטוט  <--apply--  דוח + תיקיית ניסיון  <--import--  תשובת JSON
```

## ייצוא

```bash
python -m sketch2cad.bridge export <תיקייה> --out <חבילה> [--drawing <קוד>] [--request "..."]
python -m sketch2cad.bridge export <תיקייה> --to-outbox [--drawing <קוד>] [--request "..."]
```

`--to-outbox` כותב את החבילה אל `<פרויקט>/agent_exchange/outbox/<זמן>_<קוד>/` ויוצר גם את `agent_exchange/inbox/`. בממשק הכפתור «שלח לסוכן» עושה את זה. ב«סימון ותיקון לפי בקשה» הוא שולח את הטקסט משדה «מה לשנות» ואת הגיליון המסומן, אם סומן. בלשונית «סקיצה / צילום» הוא שולח את המקורות ואת הטקסט «מה לשרטט או לשנות», גם כשאין עדיין מפרט. אם השדה ריק נפתח דיאלוג קצר.

`<תיקייה>` היא תיקיית פרויקט (`project.json`) או תיקיית שרטוט (`document.json`). בפרויקט עם יותר משרטוט אחד חובה `--drawing`.

החבילה:

| קובץ | תוכן |
|---|---|
| `manifest.json` | גרסה, קוד פרויקט ומסמך, יחידות, שפה, שמות קבצים, sha256, פריטי קטלוג שבשימוש, מעטפת ההחזרה, כללי הדיוק |
| `AGENT.md` | הוראות לסוכן, כולל כללי הדיוק |
| `spec_format.md` | סעיף 1 מ-`docs/FORMATS.md` (אותה חתיכה ש-`_spec_format()` נותן) |
| `catalog.txt` | שורות `id \| category \| name \| dimensions` כמו `_catalog_lines`. אם יש spec, נכללים הפריטים שהוא מצטט וכל פריט מאותה קטגוריה; בלי spec, כל הקטלוג |
| `spec.json` | העתק מדויק של ה-spec הנוכחי, אם יש |
| `sources/` | סקיצות, תמונות ו-PDF מתיקיית המקורות. לא מיילים, לא DXF, לא קבצי הגדרות |
| `preview.png` | הגיליון המסומן האחרון מ-`markups/markup_*.png`, ואם אין — תצוגת השרטוט |
| `request.txt` | בקשת התיקון, רק אם נמסרה ב-`--request` או `--request-file` |

החבילה לא כוללת `settings.json`, `.env` או `data_home.txt`. קובץ מקור שמכיל `ANTHROPIC_API_KEY`, `anthropic_api_key` או `sk-ant-` לא מועתק: אלה סימני סוד מקבצים ישנים, לא לקוח API. אם הסוד נמצא ב-spec או בבקשה, הייצוא נעצר והתיקייה נמחקת.

## ייבוא

```bash
python -m sketch2cad.bridge import <תשובה.json> --drawing <תיקיית שרטוט> [--trial <תיקייה>] [--apply]
python -m sketch2cad.bridge import --from-inbox --drawing <תיקיית שרטוט> [--trial <תיקייה>] [--apply]
```

`--from-inbox` קורא את קובץ ה-JSON החדש ביותר ב-`<פרויקט>/agent_exchange/inbox/`. בממשק, «קבל מהסוכן» מריץ את זה בלי `--apply`, מציג בדיקות ואזהרות, ומחליף את ה-spec רק אחרי «החל על השרטוט». אחרי ההחלה השרטוט מופק מחדש לתיקיית המסמך.

אם יש ממיר DWG, תיקיית הניסיון מקבלת גם `trial.dwg`. בלי ממיר הדוח רושם `dwg.produced: false` והסיבה, והייבוא נשאר הצליח.

התשובה היא אובייקט JSON, גם בתוך גדר ` ```json `. המעטפת:

```json
{"spec": {}, "changes": [{"en": "", "he": ""}], "assumptions": [{"en": "", "he": ""}], "questions": [{"en": "", "he": ""}]}
```

הייבוא קורא ל-`parse_reply` ול-`normalize_spec`, מריץ `run_checks`, ומרנדר DXF, PDF, PNG ו-DWG לתיקיית הניסיון. `report.json` באותה תיקייה מכיל ממצאי בדיקות, אזהרות, קבצי פלט, שגיאות, ואת כללי הדיוק.

`--apply` פועל רק אחרי רינדור שהצליח: `spec.json` הקודם מועתק ל-`spec_history/spec_<זמן>.json` (אותה תבנית שהמסך "בטל תיקון אחרון" משחזר ממנה), ואז נכתב ה-spec המאומת. בלי הדגל, ובכל כשל, הקובץ הקיים לא משתנה. תוצרי הרינדור לא מועתקים לתיקיית השרטוט.

קוד יציאה: 0 הצלחה, 1 תשובה שנדחתה, 2 תיקייה או ארגומנט לא תקינים.

## דיוק בתיקון

לא נמצא בריפו מסמך דרישות בשם "פפיס". השם מופיע כחתימת בודק ב-`tests/test_mail.py` וכדוגמה למייל בודק ב-`docs/SPEC.md` (סעיף 12, פריט 6).

הוראות החבילה והדוח משתמשים בכללי התיקון שב-`sketch2cad/bridge.py` (`PRECISION_RULES`): לשנות רק את מה שהבקשה והסימונים מבקשים, לשמור יחידות, קנה מידה, נייר וכל אלמנט, מזהה, מידה, שורת מקרא, הערה והגדרה שלא התבקש לשנות, ולדווח הנחות ושאלות.

## בקרת שרטוט

`run_checks` מריץ את הבדיקות ההנדסיות הקיימות ואז את בקר השרטוט (`sketch2cad/qa.py`). כל ממצא הוא `error`, `warning` או `info`, עם `code`, מזהי אלמנטים, וניסוח בעברית ובאנגלית. הייבוא כותב אותם ל-`report.json` בשדה `checks`. אם אפשר לצייר את הגיליון, נשמר גם `qa_overlay.png` ליד תוצרי הניסיון: תצוגת הניסיון המקורית (טקסט וקווים) מוצגת דהויה, וכל אלמנט שנפגע מסומן במלבן צר משלו — שגיאה באדום, אזהרה בכתום. המלבן חסום בגודלו. ממצא בלי מיקום על הגיליון (עובי קו, שכבה 0 וכדומה) אינו מסומן על השרטוט. המספרים שעל הסימונים מוזחים כשהם קרובים, וטבלת ממצאים בשולי הגיליון מפרטת מספר, חומרה, קוד, מזהה אלמנט וניסוח קצר בעברית. השם נרשם ב-`qa_overlay` וב-`outputs`.

ב«קבל מהסוכן» הממצאים מקובצים לפי חומרה (שגיאות, אזהרות, הערות), ומתחתיהם מוצגת שכבת הבדיקה. שגיאה חוסמת את «החל על השרטוט» עד שהמשתמש מסמן במפורש שהוא עבר על השגיאות. אזהרה אינה חוסמת.

ההגדרות הן אובייקט `qa` ב-`project.json`. אחריו גובר `spec.qa` ואז `spec.params.qa`. אובייקט ריק משאיר את ברירת המחדל. במסך הגדרות הפרויקט יש שדה JSON לאותו אובייקט.

| מפתח | ברירת מחדל | משמעות |
|---|---|---|
| `min_text_mm` | 2.5 | מינימום לטקסט כללי ולתוויות, מ"מ נייר (ISO 3098) |
| `min_annotation_mm` | 1.8 | מינימום להערת שוליים: מידה, טבלת מקרא, כיתוב כותרת, והערות הגיליון. גובה ברירת המחדל 2.0 מ"מ הוא אזהרת סדרה, לא שגיאה |
| `text_heights_mm` | 2.5, 3.5, 5, 7 | הסדרה המותרת |
| `annotation_heights_mm` | 1.8 | גובה נוסף שמותר רק להערת שוליים |
| `lineweight_min_mm` / `lineweight_max_mm` | 0.18 / 0.70 | עובי קו לפי ISO 128 |
| `thick_thin_ratio` | 2 | הקו העבה לפחות פי שניים מהדק. הזוג 0.18 / 0.35 מתקבל |
| `dim_tolerance_mm` | 1 | סטייה מותרת בין טקסט מידה לערך המדוד, ובין היסט מוצהר לגיאומטריה |
| `slope_tolerance_mm` | 1 | סטייה מותרת בין הפרש רומים לבין שיפוע × אורך |
| `min_slopes` | 150 מ"מ 1.5%, 200 מ"מ 1.0%, 250 מ"מ 0.7%, 300 מ"מ 0.5%, 400 מ"מ 0.4%, 500 מ"מ 0.3%, 600 מ"מ ומעלה 0.25% | שיפוע מינימלי לניקוז גרביטציוני לפי הקוטר |
| `sn_cover_mm` | SN2 800, SN4 600, SN8 450, SN16 300 | כיסוי מינימלי במ"מ לפי דרג קשיחות. ערכי פתיחה של המשרד, לא ציטוט של מפרט תאגיד |
| `utility_submission` | true | אזהרות הגשה לתאגיד מים (למשל מי שמש) |

שיפוע נרשם כיחס (0.015), או כאחוז כש-`slope_unit` הוא `percent` או כשהתווית היא `SLOPE 0.4%`. בלי יחידה מפורשת המספר הוא יחס, לא ניחוש. רומי INV הם ביחידות השרטוט, בשדה `inv` של הצינור או בשני טקסטי `INV` / `INV.` עם `pipe` שמפנה אליו. רום במטרים על שרטוט במ"מ (225.00 לאורך של עשרות מטרים) מתקבל. האורך נמדד בין שני הרומים, לא לאורך כל הצינור. אם חסר שיפוע, זוג רומים או קוטר, נרשמת הערה `slope_unchecked` ולא שתיקה. `sn` ו-`cover` על הצינור (או `sn` בפריט הקטלוג) מפעילים את בדיקת הכיסוי. `offset`, `offset_from` (נקודה או מזהה) ו-`offset_axis` (`x` / `y` / מרחק) על מחבר. `nts: true`, או הטקסט NTS / N.T.S. במבט, ב-`views`, בשדה קנה המידה או בטקסט, פוטר מידה שדורסת את הערך המדוד.

| קוד | חומרה | מה נתפס |
|---|---|---|
| `text_overlap` | error | שתי תיבות טקסט, תווית או טקסט מידה נחתכות. הגודל הוא גובה הטקסט כפול קנה המידה; תווית דו-לשונית היא שתי שורות |
| `text_over_line` | error | תיבת תווית או טקסט חוצה גיאומטריה מצוירת, מלבד הקו המוביל שלה |
| `outside_sheet` | error | גיאומטריה או טקסט מחוץ לשטח השרטוט השימושי |
| `in_titleblock` | error | חפיפה עם כותרת הגיליון או עם אזור ההערות. טקסט הכותרת והמקרא שיושבים שם בכוונה אינם נספרים |
| `text_too_small` | error | גובה מוקטן על הנייר מתחת למינימום של התפקיד |
| `text_height_standard` | warning | גובה שאינו בסדרת ISO 3098 (1.8 מ"מ מותר רק להערת שוליים) |
| `text_height_inconsistent` | warning | לאותו תפקיד יותר מגובה אחד |
| `dim_override` | error | טקסט המידה דורס את הערך המדוד מעבר לסטייה. מותר רק במבט NTS |
| `dim_zero` | error | מידה באורך אפס |
| `dim_duplicate` | warning | אותה מידה פעמיים |
| `slope_mismatch` | error | לצינור עם שיפוע ושני רומי INV, ההפרש אינו שווה לשיפוע × האורך |
| `min_slope` | warning | שיפוע נמוך ממינימום הניקוז לפי הקוטר |
| `slope_unchecked` | info | אי אפשר לבדוק שיפוע: חסר שיפוע, זוג רומים או קוטר |
| `sn_cover` | warning | כיסוי קטן מהערך שהוגדר לדרג ה-SN |
| `connector_offset` | error | היסט מוצהר של מחבר אינו תואם את הגיאומטריה |
| `duplicate_id` | error | מזהה אלמנט או מספר מקרא כפול |
| `unknown_ref` | error | תווית מפנה לפריט או למזהה שאינם קיימים (`#id` או `item:id`) |
| `unsourced_dims` | warning | מידות קטלוג בלי מקור. הבדיקה הקיימת נשארת |
| `lineweight_range` | warning | עובי קו מחוץ ל-0.18–0.70 מ"מ |
| `lineweight_ratio` | warning | הקו העבה קטן מפי שניים מהקו הדק |

שלוש האזהרות האחרונות, יחד עם `layer_0` ו-`defpoints`, הן כללי ההגשה לתאגיד. הן כבויות כש-`utility_submission` הוא false.

## אזהרה

חבילת עבודה של שרטוט לקוח לא נכנסת לריפו הציבורי. הדוגמאות ב-`examples/` הן חומר הדגמה של הריפו, לא חבילה מיוצאת.
