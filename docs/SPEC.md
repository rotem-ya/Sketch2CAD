# Sketch2CAD – מסמך אפיון (טיוטה לאישור)

> גרסה 0.1 · 07/10/2026 · סטטוס: **לאישור לפני כתיבת קוד**

## 1. מטרה

תוכנה מקומית שהופכת סקיצות, צילומים, מיילים וקבצי PDF לשרטוטי AutoCAD: DWG, DXF ו-PDF. התוכנה מנהלת פרויקטים ומסמכים עם קוד פנימי, תבניות כותרת וחיפוש, בעברית, באנגלית או בשתיהן.

**החלטות שנסגרו:**

| נושא | החלטה |
|---|---|
| איפה רצה | מקומית על המחשב, Windows. הממשק נפתח בדפדפן מקומי, בלי שרת חיצוני |
| שילוב | תוכנה עצמאית. **אין שילוב עם "מידה"** |
| ריפו | `rotem-ya/Sketch2CAD`, פרטי |
| סדר פיתוח | גמיש |

## 2. ארכיטקטורה

```
Sketch2CAD/
├── sketch2cad/                 ← מנוע (Core) – ללא ממשק, ניתן לבדיקה
│   ├── projects/               ← פרויקטים, תיקיות, project.json
│   ├── documents/              ← מאגר מסמכים, קודים, מהדורות
│   ├── search/                 ← אינדקס SQLite FTS5
│   ├── io/                     ← קריאה/המרה: DXF, DWG, PDF, תמונות
│   ├── drawing/                ← מנוע שרטוט: רכיבים, מידות, בלונים, מקרא
│   ├── templates/              ← מסגרות ותבניות כותרת
│   ├── i18n/                   ← עברית/אנגלית, טיפול RTL
│   └── ai/                     ← סקיצה/תמונה → מפרט JSON (Claude API)
├── app/                        ← ממשק Streamlit (מקומי)
├── catalog/                    ← נתוני אביזרים מהקטלוגים (YAML)
├── templates/                  ← תבניות כותרת מוכנות (YAML)
├── tests/
├── prototypes/                 ← הסקריפטים מהסשן הראשון (גמל, תעלות)
└── run.bat                     ← הפעלה בלחיצה (Windows)
```

**טכנולוגיות:**

| רכיב | בחירה | הערה |
|---|---|---|
| שפה | Python 3.12 | |
| ממשק | Streamlit | מוכר לך, מהיר לפיתוח. המנוע לא תלוי בו, אז אפשר להחליף אותו בעתיד |
| DXF | ezdxf | נבדק בסשן הזה |
| DWG | ODA File Converter, מותקן בנפרד | חינם לשימוש פנימי. הנתיב אליו מוגדר בהגדרות |
| PDF | PyMuPDF | תצוגה, טקסט וגרפיקה וקטורית. ⚠️ רישיון AGPL: תקין לשימוש פנימי |
| עברית | python-bidi | רק ליצירת PDF ותמונות. ב-DXF ו-DWG העברית נשמרת בסדר רגיל (נבדק ב-AutoCAD) |
| חיפוש | SQLite FTS5 | מובנה, ללא שרת |
| AI | Claude API (vision) | שלב מאוחר. דורש מפתח API |

## 3. מבנה נתונים

### 3.1 פרויקט: `project.json` בתיקיית הפרויקט

```json
{
  "id": "20117",
  "code": "20117",
  "name": {"he": "חצרים – אתר 20117", "en": "Hatzerim Site 20117"},
  "client": "USACE / CDM Smith",
  "root_folder": "D:/Projects/20117_Hatzerim",
  "language_mode": "en | he | both",
  "doc_code_pattern": "{PRJ}-{DISC}-{SUBJ}-{SEQ:02}",
  "default_titleblock": "usace_a1",
  "disciplines": {"W": "Water", "D": "Drainage", "S": "Sewage", "E": "Electrical"},
  "created": "2026-10-07"
}
```

### 3.2 מסמך: `document.json` בתיקיית המסמך

```json
{
  "code": "20117-W-CAMEL-01",
  "rev": "C",
  "title": {"he": "חיבור לגמל קיים", "en": "Connection to Existing Camel"},
  "description": "As-made, RFI-0021",
  "discipline": "W",
  "type": "as-made | shop-drawing | proposal | detail | import",
  "tags": ["RFI-0021", "camel", "6in"],
  "status": "draft | submitted | approved",
  "titleblock": "usace_a1",
  "title_overrides": {"line3": "RFI-0021 - AS-MADE"},
  "sources": ["sources/IMG_6240.JPG", "sources/sketch.jpg"],
  "spec": "spec.json",
  "outputs": {"dwg": "...RevC.dwg", "dxf": "...", "pdf": "...", "preview": "preview.png"},
  "revisions": [{"rev": "A", "date": "2026-10-06", "note": "first draft"}]
}
```

### 3.3 קוד פנימי למסמכים
- התבנית מורכבת מאסימונים: `{PRJ}` `{DISC}` `{SUBJ}` `{TYPE}` `{SEQ:02}` `{YYYY}`. לכל פרויקט מגדירים תבנית משלו.
- המספר הרץ מתקדם אוטומטית, ולא ייתכן קוד כפול באותו פרויקט.
- המהדורה (A, B, C…) נשמרת בנפרד מהקוד. עם כל מהדורה נשמר תיעוד: תאריך ומה השתנה.

## 4. תיקיות ושמירה

```
<תיקיית הפרויקט>/                ← קבועה לכל פרויקט, ניתנת לשינוי
├── project.json
├── 00_Sources/                   ← קבצים נכנסים כלליים (מיילים, תוכניות מזמין)
├── 10_Drawings/
│   └── 20117-W-CAMEL-01/
│       ├── document.json
│       ├── spec.json             ← הגדרת השרטוט (קלט למנוע)
│       ├── sources/              ← סקיצות/תמונות של המסמך
│       ├── 20117-W-CAMEL-01_RevC.dwg / .dxf / .pdf
│       └── preview.png
├── 20_Imports/                   ← קבצים שהומרו (PDF→DWG וכו')
└── 90_Archive/                   ← מהדורות קודמות
```

- **מקור האמת הוא תיקיית הפרויקט.** אינדקס החיפוש נשמר ב-`%APPDATA%/Sketch2CAD/index.db` ואפשר לבנות אותו מחדש מהתיקיות בכל רגע.
- **שינוי תיקיית פרויקט:** אפשר להעביר את כל הקבצים, או רק לקשר מחדש לתיקייה שכבר הועברה.

## 5. שפה

- **שפת הממשק:** עברית (RTL) או אנגלית, בבחירת המשתמש.
- **שפת השרטוט** נקבעת בכל פרויקט, ואפשר לשנות אותה במסמך בודד:
  - EN
  - HE
  - דו-לשוני: מקרא עם עמודת אנגלית ועמודת עברית, כמו שנבדק בסשן הזה.
- כל רכיב בקטלוג ובתבניות מחזיק תיאור בשתי השפות.

## 6. תבניות וכותרות
- תבנית מוגדרת בקובץ YAML: גודל גיליון, מסגרת, שדות ומיקומם, לוגו, תוויות בעברית ובאנגלית.
- תבניות התחלתיות:
  - A1 בסגנון USACE: מה שעשינו בגמל.
  - A3 פשוט: שורות כותרת.
  - A3 עם מקרא דו-לשוני.
- כל תבנית שמורה לשימוש חוזר. בכל מסמך אפשר לשנות כותרת בלי לגעת בתבנית.

## 7. קריאה והמרה של קבצים

| קלט | מה עושים | פלט |
|---|---|---|
| DXF | קריאה ישירה, תצוגה מקדימה, טקסט לאינדקס | DWG, PDF |
| DWG | המרה ל-DXF (ODA) ← כמו DXF | DXF, PDF |
| PDF וקטורי (יוצא מ-CAD) | חילוץ קווים, קשתות וטקסט ← ישויות DXF, עם כיול קנה מידה (בחירת קנה מידה או מידה ידועה) | DXF, DWG |
| PDF סרוק / תמונה | שיבוץ כתמונת רקע (IMAGE) ב-DXF בקנה מידה נכון. **המרה לקווים אינה מדויקת** ובשלב מאוחר תיעשה בעזרת AI | DXF/DWG עם רקע |
| סקיצה / צילום | שלב AI: מפרט JSON ← מסך בדיקה ← שרטוט | spec.json ← DWG/PDF |

## 8. מנוע השרטוט
- **קלט:** `spec.json` – רכיבים, מיקומים, תוויות ומידות. **פלט:** DXF, ממנו DWG ו-PDF.
- **ספריית רכיבים, התחלה ממה שכבר נבנה:**
  - צנרת ישרה וקשתות
  - הסתעפות T
  - אוגן
  - מגוף, במבט חזית ובמבט על
  - מחבר פקסגול / גולן
  - שוחה עם מכסה אטום או רשת
  - תעלת ניקוז
  - גוש עיגון
  - קו קרקע וסוללה
  - מידות שרשרת
  - בלונים ומקרא
  - פרט מוגדל
- **קטלוג אביזרים (YAML):** מידות האביזרים לפי ההגשות המאושרות, למשל AVK 06/61 DN150: L=210, H=448 וכו'. מוסיפים לו אביזרים לאורך הזמן.

## 9. מסכים

1. **בית:** רשימת פרויקטים, חיפוש כללי, פרויקט חדש.
2. **פרויקט:**
   - רשימת מסמכים, מסוננת לפי תחום, סוג וסטטוס.
   - חיפוש לפי קוד, כותרת, תיאור או תגית.
   - מסמך חדש.
   - הגדרות הפרויקט: תיקייה, תבנית קוד, ברירות מחדל.
3. **מסמך:**
   - תצוגה מקדימה ופרטים.
   - מהדורות, ויצוא DWG, DXF ו-PDF.
   - פתיחת התיקייה.
4. **ייבוא והמרה:** גרירת קבצים (PDF, DWG, DXF, תמונות), המרה ושמירה בפרויקט.
5. **תבניות:** עריכת תבניות כותרת ותצוגה מקדימה.
6. **הגדרות:** שפה, נתיב ל-ODA File Converter, מפתח Claude API.

## 10. שלבי פיתוח וקריטריוני קבלה

| שלב | תכולה | "גמור" כאשר |
|---|---|---|
| **M1 – תשתית** | פרויקטים, תיקיות, מסמכים, קוד פנימי, מהדורות, חיפוש, שפה, הגדרות | יצירת פרויקט ← מסמך ← חיפוש לפי קוד וכותרת עובד; התיקייה נוצרת כמתואר |
| **M2 – קבצים** | קריאה ותצוגה של DXF, DWG, PDF ותמונות; DXF↔DWG; PDF וקטורי→DWG; רקע לסרוקים | תוכנית CG104 (PDF) נפתחת ב-AutoCAD כקווים בקנה מידה נכון |
| **M3 – תבניות** | מסגרות וכותרות YAML, שינוי כותרת במסמך, מקרא דו-לשוני | מסמך עם כותרת מותאמת יוצא ל-DWG ול-PDF בעברית ובאנגלית תקינות |
| **M4 – מנוע שרטוט** | ספריית רכיבים, קטלוג, spec.json → DWG/PDF | הגמל ותעלות מבנה P משורטטים מחדש מ-spec.json בלבד |
| **M5 – AI** | סקיצה, צילום או מייל → spec.json → מסך בדיקה → שרטוט | סקיצת התעלות הופכת לטיוטה שדורשת רק תיקונים קלים |

**סדר מומלץ:** M1 ← M3 ← M4 ← M2 ← M5. כך כבר אחרי M4 התוכנה עושה את מה שעשינו כאן ידנית.

## 11. סיכונים והחלטות פתוחות
- **רישיונות:** ODA ו-PyMuPDF חינמיים לשימוש פנימי. אם התוכנה תימכר יידרשו רישיונות, או החלפה בחלופות קוד פתוח.
- **PDF סרוק → DWG:** איכות ההמרה מוגבלת, והציפייה צריכה להיות בהתאם.
- **התקנה על Windows:** תתבצע בסקריפט התקנה אחד (Python + ספריות). ODA מותקן בנפרד, פעם אחת.
- **גיבוי:** תיקיות הפרויקטים יכולות לשבת בתיקייה מסונכרנת (Google Drive / OneDrive).
